A complete mail workflow

From collection to action, without a patchwork of wrappers.

Postra keeps business behavior in one application core, so the web workspace, automation scripts, and AI agents follow the same policies.

IN

Secure account collection

Connect POP3 or IMAP for inbound mail and SMTP for sending. Credentials are registered through an encrypted secret store rather than passed to AI tools.

AI

Triage & action cards

Structure intent, priority, deadlines, reply needs, and next steps. Action cards can produce hand-off payloads for calendar, Jira, or ITSM integrations.

RRF

Hybrid search

Combine full-text and embedding results with Reciprocal Rank Fusion, group by thread, and optionally rerank with an AI model.

OK

Approval-bound sending

AI can create a draft, but sending requires a one-time token bound to the exact recipient, subject, and body payload.

SSO

Identity & isolation

Use local Argon2id accounts or Keycloak OIDC with Authorization Code Flow and S256 PKCE. User mailboxes and related data are isolated.

OPS

Operations built in

Run scheduled sync, automation rules, team inboxes, legal hold, audit search, health probes, metrics, and backup workflows from one service.

Security model

Treat messages as data, not instructions.

Email is untrusted input. Postra separates it from system prompts, keeps secrets out of tool arguments, and places a human checkpoint before consequential actions.

Deployment note: when full-text search is enabled, its index contains searchable message text. Disable FTS if your policy requires the search index itself to remain encrypted.
01

Envelope-encrypted secrets

Mail passwords and API keys are stored through KEK/DEK encryption. Secret handles are not serializable into MCP or LLM context.

02

Encrypted content at rest

With encryption enabled, raw MIME, attachments, and parsed message bodies are encrypted with AES-256-GCM. Search and sorting metadata remain queryable.

03

Attachment & DLP policy

Inspect archive limits, risky extensions, quarantine states, and configured sensitive-data patterns before download or external sending.

04

Fail-safe MCP access

Tools are classified by risk level. Role ceilings, allowlists, and denylists apply before a call reaches the shared application core.

Quick start

Connect one account and see the entire path.

Build the binary, initialize local configuration, register a credential through the non-echoing TTY flow, connect an account, and start the unified service.

Open the full guide ↗
terminal
# Build and initialize
go build -o postra ./cmd/postra
./postra init

# Register the password securely
./postra secret set --type mail_password --label "Work mailbox"

# Test, sync, and serve after adding the account
./postra account test --id acc_xxx
./postra sync --account acc_xxx --wait
./postra serve

FAQ

Before you deploy.

A few details that matter when email and AI share the same workflow.

Does Postra replace my mail server?

No. Postra connects to existing POP3 or IMAP accounts for collection and SMTP for sending. It adds a self-hosted workspace, automation, search, AI assistance, and controlled actions around that infrastructure.

Can an AI agent send mail without a person?

The intended flow separates drafting from sending. A send request requires a one-time approval token bound to the exact recipient, subject, and body; changing the draft invalidates the token.

Can Postra run without an external AI provider?

Core mail collection, browsing, full-text search, rules, drafts, and sending do not require an AI call. AI-powered analysis and embeddings use a configured OpenAI-compatible endpoint and follow the administrator's external-data policy.

Which storage backend should I use?

SQLite is designed for embedded or single-instance use. PostgreSQL supports server and multi-user deployments and can use pgvector for accelerated semantic search. Review the multi-node constraints in the README before scaling replicas.
