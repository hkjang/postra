# 운영 설정과 개인 설정

Postra의 운영 설정은 `/app/admin` 운영 콘솔, 개인 설정은 `/app/settings`, 계정별 설정은 `/app/accounts/<id>/preferences`에서 관리한다. 운영 콘솔의 검색은 표시 이름뿐 아니라 설정 키와 환경변수 이름도 찾는다. 예를 들어 `POSTRA_AI_BASE_URL`을 입력하면 AI Endpoint 항목이 표시된다.

## 적용 우선순위

`프로그램 기본값 → 설정 파일/환경변수 초기값 → 관리자 기본값 → 사용자 설정 → 계정별 설정`

관리자가 **관리자 값 강제 적용**을 선택한 개인화 항목은 사용자·계정 설정보다 우선한다. 메일 프로토콜, TLS, 외부 AI 허용, 발송 제한, 첨부 정책 등 전역 보안 정책은 개인 설정에 노출하지 않는다. HTML 발송 금지와 알림 전체 끄기도 관련 개인 설정보다 우선한다. 계정 ID와 서명 ID는 각 사용자의 이름공간에 속하므로 전역 기본값이나 전역 강제값으로 지정할 수 없다.

환경변수는 프로세스 시작 때 읽는다. 저장한 관리자 값은 재시작 후에도 환경변수보다 우선한다. 운영 요청에서 환경변수를 다시 읽어 정책을 결정하지 않는다. 코드의 정의는 `internal/platform/config/bindings.go`와 `internal/application/settings_catalog.go`, 실제 값 조회는 `App.Setting`, `App.EffectiveConfig`, `App.PersonalSettings`에서 관리한다. REST와 MCP는 같은 application service를 호출한다.

각 항목의 **값 출처 및 환경변수**를 펼치면 기본값·환경변수·배포 설정 파일·관리자·사용자·계정·강제 정책 중 어디에서 온 값인지 볼 수 있다. 사용자·계정의 **기본값 상속으로 복원**은 해당 계층의 값만 해제한다.

## 반영 시점

| 표시 | 의미 | 대표 항목 |
| --- | --- | --- |
| 즉시 적용 | 저장 후 다음 요청/작업부터 적용. 이미 진행 중인 SMTP 전송이나 AI 호출을 소급 취소하지 않음 | AI Endpoint/키/모델/한도, 발송/DLP/첨부 정책, MCP 권한·요청 timeout, UI 개인화 |
| 작업 루프 반영 | 워커가 최대 5초마다 새 주기·사용 여부를 확인. 동시성 축소는 실행 중 작업을 강제 종료하지 않고 새 작업부터 제한 | 자동 동기화·임베딩·분류·브리핑, 계정별 동기화 |
| 재시작 필요 | 저장값과 현재 실행 값을 구분하고 적용 대기 표시 | HTTP/MCP listen 주소, MCP endpoint/session timeout, 인증 사용 여부, worker/metrics/telemetry/Web UI 사용 여부 |
| 배포 초기값 | 서버/저장소를 여는 값이므로 UI에서는 조회만 가능 | 데이터 경로, SQLite/PostgreSQL 선택·DSN, 초기 관리자, 초기 API token, at-rest 암호화 |
| 항상 적용 | 프로그램의 고정 안전 정책. 관리자·개인 설정·환경변수로 해제할 수 없고 과거 저장값도 무시 | 외부 메일 포함 모든 발송의 명시적 승인 필수 |

저장소 이동, 암호화 방식 변경, KEK 교체는 데이터 마이그레이션/백업·복구 절차가 필요하다. UI에서 값을 바꾸는 것만으로 수행하지 않는다. 과거 DB에 남은 `security.encrypt_at_rest` 값이 실제로 생성된 저장소 어댑터의 암호화 상태를 덮어쓰지 않도록 배포 설정을 기준으로 고정한다. KEK는 외부 `POSTRA_KEK` 또는 기존 공유 DB keyring 방식을 유지한다.

실시간 정책 변경은 새로운 요청에 적용되며 SSE의 개인 설정 revision 변경을 통해 열린 다른 브라우저에도 갱신된다. SSE가 끊기면 주기적 조회로 대체한다. 기존 장시간 연결의 인증과 MCP scope도 다시 검증한다. 자세한 워커 동작은 [LIVE_WORKERS.md](LIVE_WORKERS.md), 알림은 [NOTIFICATIONS.md](NOTIFICATIONS.md)를 참고한다.

## 운영 콘솔

일반 / 인증 및 SSO / 메일 / AI / 검색 및 임베딩 / MCP / 발송 정책 / 첨부파일 / 동기화 / 보안 / 알림 / 저장소 / 시스템 / 사용자 관리 / 감사 로그로 나뉜다.

상단 상태에서 **정상**은 확인된 DB 연결 상태, **설정됨·연결 미확인**은 설정만 존재하는 상태다. AI·OIDC·메일 설정이 있다는 이유로 실제 연결 성공을 표시하지 않는다. 저장 전 변경 확인에서는 바뀌는 값과 강제 정책, 재시작 항목을 검토한다. 다른 운영자가 먼저 저장한 경우 revision 충돌로 이전 화면의 덮어쓰기를 거부한다.

관리자 설정 저장은 SQLite/PostgreSQL 트랜잭션 안에서 공개 설정 snapshot을 비교하고 변경한다. 서로 다른 서버 인스턴스에서 동시에 같은 revision을 저장해도 하나만 성공하며 나머지는 충돌한다. 비밀값 저장 후 COMMIT 응답이 유실되면 DB 참조 여부를 확인하여 실제로 저장된 키를 폐기하지 않는다. 개인 설정 revision은 사용자·계정에 묶지만 개인 설정 저장 자체의 다중 프로세스 CAS를 보장하는 것은 아니다. 이 방어가 백그라운드 워커의 leader election이나 멀티 replica 운영 지원을 의미하지는 않는다.

사용자 관리·이메일 기반 SSO 메일 프로비저닝·이전 소유자 메일 정리·장애 기록·감사 로그·MCP 토큰 관리도 콘솔에서 접근한다. 관리자는 운영 권한을 가질 뿐 다른 사용자의 메일·본문·초안·첨부·개인 서명을 읽는 우회 권한을 갖지 않는다.

## AI와 연결 시험

기본 Chat/Embedding 모델, 별도 임베딩 Endpoint, API Key, 암호화한 게이트웨이 추가 헤더, timeout, 출력 토큰, Context Length, Temperature, 모델 비활성 목록, 외부 호출 허용·PII 마스킹을 관리한다. Context Length 검사는 모델별 tokenizer가 아닌 **보수적인 Unicode 문자 예산**이다. 실제 provider tokenizer 한도의 대체 보증은 아니다.

작업별 모델 표는 메일 요약(`summarize`), 작성(`compose`), 분류(`classify`), Q&A(`qa`), 다시 쓰기(`rewrite`), 브리핑(`digest`)을 제공한다. 고급 JSON에는 `model`, `base_url`, `max_tokens`, `api_key_ref`를 지정할 수 있다. `api_key_ref`는 등록된 `sec_...` 참조이며 키 원문을 넣을 수 없다. 알 수 없는 필드와 인증정보/쿼리 문자열이 포함된 URL은 저장 전에 거부한다. 임베딩은 별도 Embedding Model/Endpoint 설정을 사용한다.

선택한 작업의 실제 Endpoint를 기준으로 외부 정책을 검사한다. 사용하지 않는 외부 모델 설정 때문에 내부 모델을 차단하지 않는다. 외부 전송 PII 마스킹은 메일 분석·임베딩·검색 재순위에 적용하며, provider 어댑터에서도 해당 요청의 설정 snapshot과 대체 모델 Endpoint를 기준으로 다시 적용한다. 재순위 판단에 사용되는 메일 제목도 AI 지시문과 분리된 비신뢰 입력이다. 비활성 모델이나 보안 정책 거부는 자동 모델 대체로 우회하지 않는다.

**저장 전 AI/Embedding 확인**은 입력 중인 값으로 무해한 시험 요청만 보내고 설정·비밀값을 저장하거나 운영 provider를 교체하지 않는다. OIDC 시험은 issuer discovery와 필수 endpoint 확인이며 실제 로그인·client secret·Keycloak callback 등록 성공까지 보증하지 않는다. 변경 후 실제 SSO 로그인을 확인해야 한다. Database 시험은 현재 연결의 상태만 검사한다. 메일 계정 화면에서는 저장된 계정으로 IMAP/POP3·SMTP 단계별 연결 시험을 할 수 있으며 시험 메일을 보내지는 않는다.

## 비밀값과 감사

비밀번호, AI/OIDC/Milvus 키, 추가 API 헤더는 암호화 SecretStore에 저장하고 설정에는 참조만 둔다. 화면에는 등록 여부만 표시하며 원문을 재조회하지 않는다. 비밀값 입력란을 비워 저장하면 기존 값을 유지한다. 저장 실패 후에는 입력 중인 키를 화면 상태에서 지운다. 이전 평문 추가 헤더/Milvus 토큰은 시작 시 암호화 저장으로 이관한다. 비밀 저장소 접근이 실패하면 초기값으로 조용히 되돌리지 않는다.

감사에는 사용자·시각·transport와 변경 키별 이전/이후 값이 기록된다. 비밀값은 등록 여부만, 긴 값은 변경 사실만 남긴다. URL의 인증정보·쿼리도 감사에서 제거한다. 설정 검색 응답에 다른 사용자의 내부 개인 설정이나 서명 값은 포함하지 않는다. 연결 실패 응답은 upstream API Key/헤더를 가린 후 길이를 제한한다.

발송·동기화·연결 시험·AI 평가 DTO와 오류 감사/장애 기록·OpenTelemetry에는 원문 서버 오류를 싣지 않고 상태별 고정 안내를 사용한다. 알려진 과거 provider 진단 기록도 조회 시 안전한 안내로 바꾸며 저장된 원본 행을 일괄 삭제하거나 수정하지 않는다. OIDC는 허용된 오류 코드와 조치 안내만 노출하고 provider의 설명·응답 본문·알 수 없는 오류 코드는 버린다.

## 개인·계정 설정과 서명

사용자는 테마(Light/Dark/System), 밀도, 읽기 패널 위치, 미리보기 줄 수, AI 패널 기본 표시, 기본 발신 계정, 작성 형식·HTML 템플릿·tone·답장 길이·언어, AI 자동 요약/추천 답장, 검색 방식, 알림 범주, 날짜/locale을 지정한다. 언어/locale 선택은 HTML 언어 속성과 날짜 표현에 적용되며 운영 UI 문구는 현재 한국어 중심이다. AI 작성 언어는 별도 작성 언어 항목으로 지정한다.

계정별로 서버 연결 설정과 자동 수집 여부·주기, 작성 스타일·템플릿·서명을 재정의한다. 수집 주기 `0`은 조직 기본값 상속이며 최소 주기 정책이 우선한다. 기본 발신 계정 선택은 사용자 설정에서 한다.

`/app/settings/signatures`에서 기본/내부/고객/영문 등 여러 서명을 만들고 작성 중 선택할 수 있다. 이름·직책·부서·회사·전화·이메일·본문·선택 로고를 지원한다. 자동 서명 정책은 새 메일 전체, 첫 답장 간결, 자신의 후속 답장 생략을 지원한다. 원문/스레드 근거가 없는 경우 후속 답장이라고 추측하지 않는다. 계정에 한정된 서명은 다른 계정의 기본값으로 지정할 수 없다. 로고도 발송 외부 이미지 정책을 따른다. 자세한 보안/호환 범위는 [MAIL_RENDERING.md](MAIL_RENDERING.md)를 참고한다.

## REST 계약

정식 경로는 `/api/v1/`이며 기존 `/api/`는 호환 alias이다. 브라우저 쓰기 요청은 HttpOnly session cookie와 별도 CSRF 헤더를 사용한다.

| 경로 | 사용 |
| --- | --- |
| `GET/PATCH /api/v1/admin/configuration` | 관리자 카탈로그 조회/변경 |
| `POST /api/v1/admin/configuration/test` | 저장하지 않는 후보 설정 시험 |
| `GET /api/v1/admin/operations` | 확인된 상태와 설정 존재 상태 구분 |
| `GET/PATCH /api/v1/preferences` | 현재 사용자 개인 설정 |
| `GET/PATCH /api/v1/accounts/{id}/preferences` | 소유 계정 설정 |
| `/api/v1/signatures` | 소유자별 복수 서명 |

변경은 `values`, 쓰기 전용 `secrets`, 관리자 `locks`, 사용자 `reset`, 조회 때 받은 `revision`을 포함한다. 실패는 공통 `code`, `message`, `details`, `trace_id` 계약을 사용한다. MCP key로 REST에 접근하더라도 scope와 gateway 정책을 우회할 수 없으며 사용자/비밀정보/보안 설정 변경은 기본 MCP 인터페이스에 노출하지 않는다.
