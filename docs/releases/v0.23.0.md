# Postra v0.23.0 — DCR 호환 OAuth 프록시

v0.22.0의 Keycloak OAuth MCP 연결은 클라이언트가 Keycloak에 사전 등록된 client ID를 직접 지정할 수 있어야 했습니다. 이번 릴리즈는 동적 클라이언트 등록(DCR, RFC 7591)만 지원하는 MCP 클라이언트(claude.ai 커넥터, 일부 데스크톱·IDE 앱)도 MCP URL만으로 Keycloak SSO에 연결되도록, Postra가 클라이언트에게 OAuth Authorization Server 역할을 하고 실제 로그인은 사전 등록한 하나의 프록시용 Keycloak client로 대행하는 **DCR 호환 프록시**를 추가합니다. 기본 비활성이며 기존 사전 등록 방식과 API 키는 그대로 유지합니다.

## DCR 호환 프록시

- 관리자 MCP 설정에 `mcp.oauth.proxy.enabled`, `mcp.oauth.proxy.client_id`, 쓰기 전용 `mcp.oauth.proxy.client_secret_ref`를 추가했습니다. 프록시 client는 웹 SSO client와 달라야 하며 Postra가 자동으로 허용 client 목록에 포함합니다.
- 켜면 Protected Resource Metadata의 `authorization_servers`가 Postra origin을 가리키고, `/.well-known/oauth-authorization-server`(및 `/.well-known/openid-configuration`)에서 RFC 8414 메타데이터를, `/oauth/register`에서 RFC 7591 등록을 제공합니다. PKCE S256, `authorization_code`·`refresh_token`, `none`·`client_secret_basic`·`client_secret_post` 인증을 지원합니다.
- 등록은 익명이며 로그인 권한을 부여하지 않습니다. redirect URI는 HTTPS, loopback HTTP(포트 가변), 네이티브 앱 스킴만 허용하고, IP별 분당 제한, 30일 미사용 등록 자동 정리, 총 500개 상한을 적용합니다.
- `/oauth/authorize`는 클라이언트·redirect URI·PKCE·scope를 검사한 뒤 Keycloak으로 보내기 전에 **사용자 동의 화면**(클라이언트 이름·client ID·콜백 주소·요청 권한)을 보여 줍니다. 동의는 같은 브라우저의 일회용 쿠키에 묶이며 교차 사이트 POST는 거부합니다. 모든 DCR 클라이언트가 하나의 Keycloak client를 공유하는 프록시 구조에서 MCP 사양이 요구하는 confused deputy 방어입니다.
- `/oauth/callback`은 Keycloak code를 Postra가 봉인한 code로 감싸 클라이언트에 전달하고, `/oauth/token`은 클라이언트의 PKCE verifier·client 인증을 먼저 확인한 뒤에만 Keycloak token endpoint를 호출합니다. access token은 Keycloak이 발급한 Bearer JWT 그대로이며 refresh token은 해당 클라이언트에 묶어 봉인해 반환합니다.
- 봉인된 state·code·refresh token은 복제본이 공유하는 OIDC 상태 키에서 파생한 키로 암호화되므로 다중 replica 배포에서 별도 세션 저장 없이 동작합니다. 등록된 클라이언트만 새 테이블 `mcp_oauth_clients`(SQLite·PostgreSQL 자동 생성)에 저장됩니다.
- 사전 등록 client ID를 지정하는 클라이언트는 프록시를 켠 뒤에도 계속 동작합니다. 허용 목록의 client ID로 `/oauth/authorize`·`/oauth/token`에 오면 Postra가 요청을 그대로 Keycloak에 전달하고 redirect URI·PKCE 검증은 Keycloak이 수행합니다.
- token endpoint는 Keycloak이 발급한 access token을 `/mcp`와 같은 기준(issuer·audience·`azp`·scope·활성 사용자 연결)으로 먼저 검증합니다. Audience mapper 누락이나 사용자 미연결로 거부되면 `invalid_grant`와 점검 항목을 안내하고 관리자 장애 화면에 `mcp_oauth` 행으로 기록합니다.
- 관리자 MCP 화면에 등록된 DCR 클라이언트 목록·콜백 주소·삭제 기능(`GET/DELETE /api/admin/mcp-oauth-clients`)을 추가했습니다. 삭제하면 새 로그인과 refresh가 즉시 중단됩니다. 개인 MCP 화면은 인증 서버 안내, 등록 endpoint, 프록시 client와 Keycloak에 등록할 콜백 주소를 표시합니다.
- `mcp.endpoint`에 `/oauth` 접두사를 예약해 프록시 경로와 충돌하지 않게 했습니다.

## 검증

- 전체 Go race 테스트, Go vet, `gofmt`, canonical API 계약 재생성·검사
- React 47개 파일·392개 테스트, TypeScript 검사, 배포 자산 재빌드
- 등록 검증(HTTP 비loopback·`javascript:`·fragment·자격 증명·개수 초과 거부, public/confidential 발급, secret 해시 저장, 30일 정리·500개 상한)
- 동의 흐름(알 수 없는 client·다른 redirect URI는 리디렉션 없이 오류 페이지, PKCE·scope·resource 오류는 클라이언트로 `error` 전달, 다른 브라우저 nonce·쿠키 없음·교차 사이트 POST 거부, 거부 시 `access_denied`)
- 토큰 교환(PKCE 불일치·다른 client·state를 code로 재사용·code 재사용 거부, PKCE 검증 전 Keycloak 미호출, refresh token 봉인·client 바인딩·회전, 등록 삭제 후 refresh 거부, audience·미연결 사용자·ID token 거부와 안내, confidential client secret 검사, 프록시 client secret Basic 전달)
- HTTP 경로(비활성 시 전 경로 404, 메타데이터·PRM discovery, 프록시 헤더로 origin 위조 불가, 사전 등록 client pass-through와 Keycloak 오류 전달, 발급 토큰으로 MCP `mail_identity` 호출과 scope 제한, 등록 IP 제한)

테스트는 로컬 모의 Keycloak(discovery·JWKS·token endpoint)과 모의 메일·AI 서비스를 사용합니다. 운영 Keycloak realm이나 특정 상용 MCP 클라이언트와의 연결 시험을 완료했다는 의미는 아니므로, 운영자는 [설정 가이드 5절](https://github.com/hkjang/postra/blob/v0.23.0/docs/MCP_OAUTH.md)의 순서대로 대상 클라이언트에서 등록 → 동의 → Keycloak 로그인 → 자기 메일 조회 → 권한 거부 → 등록 삭제를 확인한 뒤 확대 적용해야 합니다.

## 업그레이드 및 호환성 주의사항

v0.22.1에서 새 필수 환경변수는 없습니다. 첫 실행 시 `mcp_oauth_clients` 테이블이 자동 생성됩니다(기존 테이블 변경 없음). DB·SecretStore·ObjectStore·KEK를 백업하고 유지한 상태에서 실행 파일 또는 컨테이너 이미지를 교체한 뒤 재시작하세요. Go 단일 실행 파일에 React 자산·글꼴을 포함하므로 폐쇄망 런타임에 Node 서버나 외부 CDN이 필요하지 않습니다.

- 프록시는 기본 비활성이며 켜지 않으면 v0.22.1과 동작이 같습니다. `/oauth/*`와 `/.well-known/oauth-authorization-server`는 비활성 상태에서 404입니다.
- 프록시를 켜려면 Keycloak에 프록시용 client를 추가하고 Valid Redirect URI에 `https://<공개 MCP origin>/oauth/callback`을, `mail.*` scope에 공개 MCP URL Audience mapper를 연결해야 합니다. confidential client를 권장하며 secret은 관리자 설정의 쓰기 전용 항목으로 입력합니다.
- 리버스 프록시는 MCP 경로와 `/.well-known/oauth-protected-resource*`에 더해 `/.well-known/oauth-authorization-server`, `/.well-known/openid-configuration`, `/oauth/*`도 전달해야 합니다. 별도 MCP listener를 쓰는 배포에서는 그 listener가 같은 경로를 함께 제공합니다.
- `/api/mcp/connection` 응답에 `oauth.authorization_server`와 `oauth.proxy` 객체가 추가됩니다. 응답을 엄격하게 파싱하는 자동화가 있다면 확인하세요.
- CIMD, `client_credentials`, introspection·revocation endpoint, DPoP는 제공하지 않습니다. Keycloak 로그아웃·사용자 중지 반영이 access token 만료까지 지연되는 v0.22.0의 한계와 짧은 수명 권장은 동일하며, 긴급 차단에는 Postra 사용자 비활성화나 DCR 등록 삭제·client 허용 해제를 함께 사용하세요.
