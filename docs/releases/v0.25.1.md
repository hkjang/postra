# Postra v0.25.1 — IMAP 계정당 연결 하나

v0.24.0 이후 IMAP 동기화가 "TCP 연결은 되었으나 서버가 세션을 시작하지 않았습니다"로 실패하는 문제를 고친 패치 릴리즈입니다. 원인은 서버 쪽 장애가 아니라 **Postra 가 한 계정에 서버 연결을 두 개 쓰고 있었던 것**입니다. 계정당 동시 접속을 적게 허용하는 서버는 두 번째 연결을 TCP 로만 받아 놓고 환영 메시지를 보내지 않으며, 그것이 위 오류로 나타납니다. 설정·환경변수 변경은 필요 없고 DB 마이그레이션도 없습니다.

## 무엇이 이 문제를 만들었나

- v0.24.0의 `fix(sync): restart dead IMAP IDLE watches` 는 실시간 수신(IDLE) 감시가 한 번 죽으면 프로세스 재시작 전까지 되살아나지 않던 버그를 고쳤습니다. 그 결과 **감시 연결이 상시 유지**되기 시작했습니다.
- 그런데 감시는 새 메일 알림을 받으면 **자기 연결을 계속 붙잡은 채** 동기화를 시작했고, 동기화는 자기 연결을 따로 열었습니다. 즉 한 계정이 항상 2개의 연결을 썼습니다. 고쳐진 감시가 죽어 있던 동안에는 연결이 1개뿐이어서 이 문제가 보이지 않았습니다.
- v0.24.0의 보낸 메일함 동기화가 세션 시간을 늘려 겹치는 구간이 더 길어졌고, v0.25.0이 실패를 단계별로 기록하게 되면서 원인이 "환영 메시지 단계에서 서버 침묵"으로 드러났습니다.

## 고친 내용

- **계정당 인바운드 연결 하나.** 실시간 수신 감시는 알림을 받으면 자기 연결을 닫고 동기화에 넘긴 뒤, 그 동기화가 끝나면 다시 연결합니다. 감시와 동기화가 같은 계정에서 동시에 접속하지 않습니다. 재현 테스트는 이전 코드에서 동시 연결 2개를 관측하고 실패합니다.
- 연결을 넘긴 사이에 도착한 메일은 재연결 때 **메일함 개수가 늘어난 것**으로 확인해 한 번 더 동기화합니다. 늘지 않았으면 다시 동기화하지 않으므로 재연결이 동기화 반복이 되지 않습니다.
- **IMAP 실시간 수신(IDLE) 사용**(`mail.idle_enabled`, 기본 켜짐) 설정을 추가했습니다. 계정당 동시 접속을 1개만 허용하는 서버라면 끄고 주기적 동기화만 사용하세요. 끄면 모든 감시 연결이 즉시 정리되고 수신은 자동 동기화 주기를 따릅니다.
- **연결 수 제한처럼 보이는 실패는 천천히 재시도합니다.** 환영 메시지·로그인 단계의 무응답/끊김과 서버의 일시 거부 코드는 3회가 아니라 **2회까지, 10초 뒤에** 시도합니다. 한도에 걸린 서버를 빠르게 재시도하는 것은 원인을 키우는 일입니다. 그 밖의 일시적 실패는 이전처럼 최대 3회(2초·5초)입니다.
- **환영 메시지 읽기에 연결 제한 시간(기본 15초)을 적용합니다.** 이전에는 명령 제한 시간(기본 60초)을 써서, 침묵하는 서버 하나가 동기화 슬롯을 1분씩 잡고 있었습니다. 이제 몇 초 만에 판정하고 슬롯을 돌려줍니다. POP3 도 같습니다.
- 진단에 **포트·보안 모드 불일치**를 알려 주는 안내를 추가했습니다. 993/995 포트를 TLS 가 아닌 모드로 접속하면 서버는 TLS 핸드셰이크를, Postra 는 환영 메시지를 서로 기다리다 둘 다 시간 초과됩니다 — 증상이 동시 접속 제한과 똑같아서 먼저 확인하도록 표시합니다.
- 동시 접속 안내에 조치까지 담았습니다: "계정당 1개만 허용하는 서버라면 관리자 설정에서 IMAP 실시간 수신(IDLE)을 끄세요".

## 검증

- 전체 Go race 테스트, Go vet, `gofmt`, canonical API 계약 검사
- 계정당 동시 연결 관측: 감시 → 알림 → 동기화 → 재연결을 여러 번 돌려 **최대 동시 연결 1개** 확인. 이전 동작으로 되돌리면 2개가 관측되어 실패
- 재연결 시 메일함 개수가 늘어난 경우에만 추가 동기화, 변화가 없으면 동기화를 시작하지 않음(반복 방지)
- `mail.idle_enabled=false` 로 모든 감시 연결이 정리되고 재연결하지 않음
- 연결 수 제한 형태의 실패에서 시도 횟수 2회와 그 기록, 그 밖의 일시적 실패는 3회 유지
- 기존 IDLE 감시 회귀 테스트(패닉 재시작, 리더 전환, 계정 목록 실패, 설정 변경 재연결) 전부 유지

테스트는 로컬 모의 메일 서버를 사용하며 운영 서버에 접속하지 않습니다.

## 업그레이드 및 호환성 주의사항

v0.25.0에서 DB 마이그레이션, 새 필수 환경변수는 없습니다. 새 설정 키 `mail.idle_enabled`(기본 `true`, 즉시 적용)가 추가됩니다. 실행 파일 또는 컨테이너 이미지를 교체한 뒤 재시작하세요.

- 이 문제를 겪고 있었다면 **업그레이드만으로 해소**되어야 합니다. 그래도 같은 오류가 남으면 계정의 포트·보안 모드(993/995 ↔ TLS)를 확인하고, 그다음 서버의 계정별 동시 접속 허용 수를 확인한 뒤 필요하면 `mail.idle_enabled` 를 끄세요.
- 실시간 수신은 알림을 받은 뒤 동기화가 끝날 때까지 잠시 끊겨 있습니다. 그 사이 도착한 메일은 재연결 때 개수 변화로 확인해 바로 가져옵니다.
- 동기화 중 실패가 잦던 계정은 재시도 간격이 길어져 실패 판정까지 최대 10초 정도 더 걸릴 수 있습니다. 반대로 침묵하는 서버는 1분이 아니라 몇 초 만에 판정됩니다.
- [동기화 실패 진단 문서](https://github.com/hkjang/postra/blob/v0.25.1/docs/SYNC_DIAGNOSTICS.md)에 "계정당 연결 하나" 절과 포트·보안 모드 조합을 추가했습니다.
