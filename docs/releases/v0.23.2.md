# Postra v0.23.2 — MCP OAuth 세션 유지·거부 사유 진단

OAuth로 연결한 MCP 클라이언트가 권한 밖 도구를 한 번 호출하면 연결 자체가 끊기던 문제를 고치고, 하나로 뭉쳐 있던 토큰 거부 사유를 원인별로 분리해 알려 주는 패치 릴리즈입니다. 새 설정 키, DB 마이그레이션, 새 필수 환경변수는 없습니다.

## scope 거부가 MCP 세션을 끊던 문제

- OAuth scope 검사 preflight가 권한이 부족한 `tools/call`을 SDK보다 먼저 가로채 **HTTP 403**으로 응답했습니다. MCP 클라이언트는 2xx가 아닌 POST 응답을 도구 오류가 아니라 전송 실패로 해석하며, Go SDK는 여기서 세션 전체를 닫습니다. 도구 92개를 광고하는 서버에 기본 scope(`mail.read mail.search`)로 접속한 agent가 범위 밖 도구를 처음 호출하는 순간 연결이 끊어졌습니다.
- preflight는 설정된 MCP endpoint 경로에서만 발동하는데 기존 테스트는 전부 핸들러를 루트(`/`)에 마운트해, 실제 배포가 사용하는 `/mcp` 경로의 이 동작을 검증하는 테스트가 없었습니다.
- `oauthScopeHint`로 바꿔 요청에 직접 응답하지 않습니다. 부족한 scope를 알리는 RFC 6750 `WWW-Authenticate` 챌린지 헤더는 그대로 붙여 OAuth 클라이언트의 scope 상향 요청을 계속 지원하되, 거부 자체는 `required_scopes`를 담은 일반 JSON-RPC 도구 오류로 돌아가고 세션은 유지됩니다.
- 실제 SDK 클라이언트를 `/mcp`로 붙여 도구 오류 반환과 세션 생존을 함께 확인하는 회귀 테스트를 추가했습니다.

## 토큰 거부 사유 진단

- Audience mapper 누락, 허용 목록에 없는 client, SSO로 먼저 로그인하지 않은 사용자, ID token 오사용 — 원인이 모두 다르고 조치도 다른데 하나의 동일한 `invalid_grant` 문장으로만 돌아왔습니다. `AuthenticateMCPOAuthTokenReason`이 사유를 구분해 DCR 프록시 token endpoint의 `error_description`, 서버 로그, 관리자 인시던트에 각각 실제 원인을 남깁니다. audience 검사를 `oidc.Config.ClientID` 대신 직접 수행해 서명 실패와 audience 불일치를 구분합니다.
- 토큰은 유효하지만 이 배포가 허용하는 scope를 하나도 담지 않은 경우, 연결과 도구 목록은 성공하고 모든 호출만 실패하는 무증상 실패였습니다. 이제 토큰 발급 시점에 경고 로그와 인시던트를 남깁니다.
- 거부 로그는 익명 호출자가 임의로 유발할 수 있으므로 출발 주소당 분당 1건으로 제한합니다. 사유 문장은 배포 구성만 지칭하며 토큰이나 그 소지자의 자격 증명을 담지 않습니다.
- 토큰 수용 정책 자체는 변경하지 않았습니다. Audience mapper와 사용자의 선행 웹 SSO 로그인 요구는 그대로입니다.

## OAuth 프록시 상호운용

- RFC 8707 `resource`를 authorization·token 요청 모두에서 Keycloak으로 전달합니다. Resource Indicator를 처리하는 버전에서는 이것만으로 audience가 채워지고, 모르는 버전은 파라미터를 무시하므로 Audience mapper 구성이 여전히 기준입니다.
- 클라이언트가 보낸 `resource`를 scheme·host 대소문자와 끝의 `/`만 정규화해 비교합니다. 사용자가 입력한 URL 표기가 달랐다는 이유로 `invalid_target`이 되지 않습니다.
- 이 배포가 더 이상 알지 못하는 client 등록(30일 미사용 정리, 관리자 폐기, DB 교체)으로 접속하면 막다른 오류 페이지 대신 클라이언트에서 연결을 삭제하고 다시 추가하라고 안내합니다.

## 검증

- 전체 Go 테스트, Go vet, `gofmt` 검사, `go mod tidy` 무변경
- CI 와 같은 플래그의 `gosec -severity medium -exclude-dir=scripts ./...`: exit 0 · Issues 0
- 수정 전 상태에서 실제 MCP SDK 클라이언트가 `/mcp`로 권한 밖 도구를 호출하면 `TRANSPORT ERROR: Forbidden` 후 `connection closed`가 재현되는 것을 확인하고, 수정 후 도구 오류 반환과 후속 호출 성공을 확인
- 모의 Keycloak으로 discovery → DCR 등록 → 동의 → 콜백 → 토큰 교환 → `initialize` 전 구간을 MCP 클라이언트와 같은 순서로 재생하고, Audience mapper 누락·미연결 사용자·ID token·`resource` 불일치·scope 미발급 각 경우의 응답을 확인
- 프런트엔드 소스 변경이 없어 포함된 `/app` 번들은 v0.23.1 과 동일

테스트는 로컬 루프백 서버와 모의 Keycloak·메일·AI 서비스를 사용하며 운영 메일 서버나 운영 데이터에 접근하지 않습니다.

## 업그레이드 및 호환성 주의사항

DB 마이그레이션, 새 설정 키, 새 필수 환경변수는 없습니다. DB·SecretStore·ObjectStore·KEK를 백업하고 유지한 상태에서 실행 파일 또는 컨테이너 이미지를 교체한 뒤 재시작하세요. 프런트엔드 소스 변경은 없으며 Go 단일 실행 파일에 React 자산·글꼴을 포함하므로 폐쇄망 런타임에 Node 서버나 외부 CDN이 필요하지 않습니다.

- OAuth로 MCP를 사용 중이라면 교체를 권장합니다. v0.23.1 까지는 권한 밖 도구 호출 한 번으로 클라이언트 연결이 끊어집니다.
- scope 거부의 HTTP 상태가 403 에서 200(JSON-RPC 도구 오류)으로 바뀝니다. 응답 상태 코드로 scope 거부를 판별하던 자체 클라이언트가 있다면 도구 오류의 `insufficient_scope` 와 `required_scopes` 를 보도록 바꾸세요. `WWW-Authenticate` 챌린지는 그대로 유지됩니다.
- 이미 발급된 access token, API Key, REST OIDC Bearer, 사전 등록 client 연결 동작은 v0.23.1 과 같습니다. [Keycloak OAuth MCP 설정](https://github.com/hkjang/postra/blob/v0.23.2/docs/MCP_OAUTH.md)과 [v0.23.0 릴리즈 내용](v0.23.0.md)을 참고하세요.
