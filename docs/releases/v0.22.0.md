# Postra v0.22.0 — Keycloak OAuth MCP 연결

기존 API 키 방식에 더해 Keycloak OAuth로 원격 MCP를 연결할 수 있습니다. Keycloak이 로그인·토큰 발급을 담당하고 Postra가 메일 접근 권한을 검증합니다. OAuth는 기본 비활성화이며 기존 API 키와 로컬 stdio 사용 방식은 유지합니다.

## OAuth 연결과 운영 화면

- 관리자 MCP 설정에 OAuth 활성화, 공개 MCP URL, 허용 Client ID, 허용 Scope를 추가했습니다. 기존 인증 및 SSO의 Keycloak Issuer를 사용하며 OAuth 정책은 다음 요청부터 적용됩니다.
- 공개 Protected Resource Metadata와 `WWW-Authenticate` 안내를 제공해 OAuth 클라이언트가 Keycloak 인증 서버를 찾을 수 있습니다. 기본 `/mcp`뿐 아니라 사용자 지정 endpoint와 별도 MCP listener를 지원합니다.
- 일반적인 단일 요청에서 권한이 부족하면 `403 insufficient_scope`로 필요한 scope를 안내합니다. 관리자가 차단한 권한은 재승인으로 우회할 수 없습니다. 큰 요청도 기존 SDK 경로에서 권한을 검증합니다.
- 개인 MCP 키 화면과 관리자 화면에서 실행 endpoint, 재시작 대기 endpoint, Issuer, Resource URL, Metadata, Client·Scope를 확인합니다. 실제 연결 성공과 설정 완료 상태를 구분하며 OAuth 토큰이나 client secret을 입력·저장하지 않습니다.

## 보안 및 기존 기능 유지

- 서명·Issuer·Audience·만료·유효 시작 시각·Keycloak access-token 유형과 허용 client(`azp`)를 검증합니다. ID token, 다른 resource의 토큰, 허용되지 않은 client는 거부합니다.
- 토큰 scope, 관리자 OAuth 허용 범위, 조직 MCP 정책, 사용자 역할과 데이터 소유권을 함께 적용합니다. 기존 활성 Postra 사용자와 `(issuer, subject)`로 연결하며 Bearer 요청에서 이메일만으로 계정을 병합하거나 새 사용자를 만들지 않습니다.
- 사용자·Issuer·Client별로 MCP 세션을 구분합니다. 토큰 갱신이나 권한 변경 뒤에도 매 요청의 권한을 다시 확인하고, 로컬 사용자 비활성화와 client 허용 해제를 다음 요청부터 반영합니다.
- MCP 자격 증명으로 새 API 키를 발급하거나 일반 REST 인증으로 우회하지 못하도록 방어를 강화했습니다. 인증을 끈 신뢰 로컬 모드에서도 명시적으로 전달한 잘못된 Bearer를 로컬 관리자 권한으로 취급하지 않습니다.
- Discovery/JWKS 요청 시간·응답 크기·반복 조회를 제한하고 토큰·메일 본문을 제외한 client·도구·오류 감사 정보를 기록합니다. MCP 오류 처리의 typed-nil 예외도 보완했습니다.
- OAuth에서도 초안 → 미리보기 → 승인 → 발송을 유지합니다. 승인 이후 내용 변경 시 기존 승인을 거부하고, 같은 idempotency key의 재시도로 중복 발송하지 않습니다.

## 활성화 순서

1. 기존 Postra 웹 SSO와 별도의 MCP client를 같은 Keycloak realm에 사전 등록합니다. Authorization Code + PKCE S256과 해당 MCP 클라이언트의 정확한 callback을 사용합니다.
2. 필요한 `mail.read`, `mail.search` 등의 optional scope를 만들고 Audience mapper에 공개 MCP URL을 정확히 지정합니다. 웹 SSO client ID나 `/auth/oidc/callback`을 MCP client 설정으로 재사용하지 않습니다.
3. Postra 관리자 → MCP에서 공개 URL·허용 Client·Scope를 저장하고 OAuth를 활성화합니다. 공개 URL 경로는 실행 endpoint와 일치해야 합니다.
4. 사용자가 먼저 Postra에 웹 SSO 로그인하여 사용자 연결을 완료한 뒤 MCP 클라이언트에서 OAuth로 연결합니다.

자세한 절차와 폐쇄망 CA·프록시·문제 해결 안내: [Keycloak OAuth MCP 설정](https://github.com/hkjang/postra/blob/v0.22.0/docs/MCP_OAUTH.md).

## 업그레이드 및 호환성 주의사항

v0.21.1에서 추가 DB 마이그레이션이나 새 필수 환경변수는 없습니다. DB·SecretStore·ObjectStore·KEK를 백업하고 유지한 상태에서 실행 파일 또는 컨테이너 이미지를 교체한 뒤 재시작하세요. Go 단일 실행 파일에 React 자산·글꼴을 포함하므로 폐쇄망 런타임에 Node 서버나 외부 CDN이 필요하지 않습니다.

- 기존 API 키·브라우저 SSO는 계속 사용할 수 있습니다. 과거 MCP에서 웹 SSO용 OIDC Bearer를 직접 사용했다면 새 OAuth MCP 설정과 별도 client/resource token으로 전환해야 합니다.
- 기존 REST OIDC Bearer는 웹 client의 Audience와 `azp`, Keycloak access-token 유형을 모두 요구합니다. ID token이나 MCP scope/resource/client가 포함된 토큰은 REST 자격 증명으로 사용할 수 없습니다.
- 지원 범위는 사전 등록 client를 지정할 수 있는 OAuth 클라이언트와 Keycloak Bearer JWT입니다. DCR/CIMD 등록 프록시, opaque token, DPoP 검증을 추가한 릴리즈가 아닙니다.
- Keycloak introspection은 사용하지 않습니다. Keycloak 로그아웃·사용자 중지의 반영은 이미 발급된 access token의 만료까지 지연될 수 있으므로 짧은 수명을 사용하세요. 긴급 차단에는 Postra 사용자 비활성화 또는 client 허용 해제를 함께 사용합니다.
- 운영에서는 HTTPS와 신뢰한 내부 CA, Postra 인증을 유지하세요. OAuth MCP 활성화가 인증을 끈 REST API까지 보호하는 것은 아닙니다.

## 검증

- 전체 Go race 테스트, Go vet, canonical API 계약 검사
- React 47개 파일·390개 테스트, TypeScript 검사, 배포 자산 재빌드
- 브라우저 로그인·OIDC·설정·사용자 격리·메일 승인 발송 E2E 3종
- 서명된 모의 Keycloak JWT의 잘못된 Issuer/Audience/client, ID token, 만료·미래 `nbf`, 미연결·비활성 사용자 거부
- 세션 client 격리, 권한 축소·확대, OAuth 401/403 안내, 커스텀 endpoint, API 키 병행, REST·쿠키 우회 차단
- OAuth 초안·미리보기·승인·발송, 변경된 초안의 기존 승인 거부, 멱등 재시도 시 SMTP 전달 1회 검증
- JWKS 교체·장애·조회 제한, 큰 응답·잘못된 요청·설정의 비밀값 노출 방지

테스트는 로컬 모의 OIDC·메일·AI 서비스를 사용합니다. 운영 Keycloak realm이나 모든 상용 MCP 클라이언트에서 연결 시험을 완료했다는 의미는 아니며, 운영 메일 발송·AI 호출·설정 변경은 수행하지 않습니다.
