# Postra v0.20.2 — AI 모델 한도 자동 감지 및 응답 안정성 개선

AI 기능에서 발생하던 Context Length 오류를 줄이기 위해 실제 선택한 모델의 실행 한도를 조회하고 요청의 출력 토큰을 자동 조정하는 패치 릴리즈입니다. 관리자 진단과 Chat·Embedding 응답 검증도 함께 강화했습니다.

## 모델별 Context 한도 자동 감지

- 설정한 OpenAI 호환 Base URL의 `/models`를 조회합니다. 예를 들어 Base URL이 `http://ai.corp.local/v1`이면 `GET /v1/models`를 사용합니다.
- 선택한 모델 ID와 정확히 일치하는 항목의 `max_model_len`, `context_length` 등 제공된 한도만 적용합니다. 다른 모델의 한도나 학습 한도(`n_ctx_train`)를 실행 한도로 추측하지 않습니다.
- 기본 Chat 모델, 작업별 모델·Endpoint와 임베딩 모델·Endpoint를 각각 확인합니다. 해당 경로의 인증과 추가 헤더, 외부 AI 호출 정책, 비활성 모델 정책을 유지합니다.
- 성공한 한도 조회는 최대 10분, 미제공·실패는 30초 캐시하며 동시 조회를 합칩니다. Endpoint·모델·인증이 바뀌면 이전 경로의 캐시를 재사용하지 않습니다. 조회 시간은 최대 3초입니다.

## 출력 토큰 조정 및 안전한 실패 처리

- 입력과 시스템 지시문의 토큰 사용량을 추정하여 남은 Context 안으로 출력 예약량을 조정합니다. 요청·관리자·작업별·서버 출력 상한 중 작은 값을 적용합니다.
- 생성 전 400/422 오류가 명확한 한도나 `max_completion_tokens` 사용 요구를 알려주는 경우에만 같은 입력으로 최대 한 번 조정해 재시도합니다. 입력 본문이나 보안 지시문을 임의로 잘라내지 않습니다.
- 출력 한도 도달, 빈 응답, 손상된 JSON, 중단된 스트림을 구분합니다. 불완전한 결과를 사용하거나 기본 모델로 다시 보내지 않습니다.
- 임베딩 응답의 개수·인덱스·차원·유효한 수치를 검사합니다. 일부만 반환된 응답을 전체 색인 성공으로 처리하거나 잘못된 벡터를 저장하지 않습니다.
- 오류 안내에는 고정된 안전한 진단을 사용하며 서버의 오류 본문이나 API Key를 노출하지 않습니다.

## 관리자 화면

- AI 설정에 **모델 Context Length 자동 감지**를 추가했습니다. 기본 활성화이며 초기 환경변수는 `POSTRA_AI_AUTO_CONTEXT_LENGTH`입니다. 저장 후 다음 요청부터 적용합니다.
- AI / 검색 및 임베딩 설정의 **모델 한도 조회**에서 생성 요청 없이 입력 중인 설정을 시험할 수 있습니다. 작업별 Chat 모델도 선택할 수 있습니다.
- 감지한 Context, 적용할 최대 출력량, 자동 감지·수동 설정·대체값·미제공 상태를 표시합니다. 설정 변경 후에는 이전 진단이나 늦게 도착한 결과를 사용하지 않습니다.
- Chat 시험에서 출력 한도에 도달한 경우를 연결·인증 실패와 구분합니다. 모델 메타데이터 미지원도 연결 실패로 단정하지 않습니다.

## 한도 미제공 서버 및 업그레이드 안내

표준 OpenAI 모델 목록에는 Context 한도 필드가 보장되지 않습니다. `/models` 미지원·메타데이터 누락·선택 모델 누락 등으로 한도를 확인하지 못하면 Chat은 관리자 **Context Length 수동·대체 한도**(`ai.context_length`, 기본 32768)를 사용합니다. 자동 감지를 끄면 해당 값을 수동 한도로 사용합니다. 임베딩 한도가 없을 때는 미제공으로 표시하며 Chat 모델의 한도를 대신 적용하지 않습니다.

입력 토큰 수는 모델별 tokenizer가 아닌 Unicode 기반 추정치입니다. 실제 서버의 계산과 다를 수 있으며 입력 자체가 한도를 초과하면 범위를 줄여야 합니다. 서버가 한도를 제공하지 않는 경우 운영 모델의 실행 한도를 관리자 대체값에 지정하세요. 자세한 동작은 [운영 설정 문서](../SETTINGS.md)를 참고하세요.

v0.20.1에서 올릴 때 추가 DB 마이그레이션은 없습니다. 기존 데이터·SecretStore·ObjectStore·KEK를 유지하고 백업 후 실행 파일 또는 컨테이너 이미지를 교체하세요. 기본 자동 감지에 따라 설정한 AI 서버에 모델 목록 조회가 추가되지만 메일 내용은 전송하지 않으며 외부 공개 모델 카탈로그를 조회하지 않습니다. 폐쇄망 Go 단일 바이너리 배포를 유지하고 런타임 Node 서버나 외부 CDN은 필요하지 않습니다.

v0.19.x 이하에서 올리는 경우 [v0.20.0 이전 안내](v0.20.0.md)의 UI·Keycloak 콜백·MCP 권한·백업 주의사항도 확인하세요.

## 검증

- Go vet, 전체 Go race 테스트, canonical API 계약 검사
- React TypeScript 검사, 전체 단위 테스트 및 모델 한도 진단 회귀 테스트
- 실제 Chromium 기반 로그인·OIDC·메일·AI·관리자 설정·승인 발송 E2E
- 모델 메타데이터·캐시·인증 격리·취소·토큰 조정·재시도 제한·오류 비밀값 보호 테스트
- 불완전한 JSON/SSE 및 임베딩 응답 검증, 관리자 권한·CSRF 검사
- 정적 보안 검사와 Go 실행 파일에 포함되는 React 정적 파일 재빌드

검증은 테스트 데이터와 mock AI·메일·OIDC 서비스를 사용합니다. 운영 AI 서버 호출이나 실제 메일 발송·운영 데이터 변경은 수행하지 않습니다.
