# Postra v0.24.0 — 보낸 메일 동기화, 동기화 중단 수정, 조직 계정 로그인

보낸 메일을 가져오고 조회하는 체계를 추가하고, 메일 동기화가 가끔 멈춘 채 돌아오지 않던 원인을 고친 릴리즈입니다. 로그인 화면은 조직 계정(SSO) 중심으로 바뀌고, silent SSO에서 로그아웃이 유지되지 않던 문제를 고쳤으며, Keycloak에 로그인한 사용자는 첫 MCP 요청에서 곧바로 Postra 계정이 연결됩니다. **DB 마이그레이션이 한 건 있습니다**(`messages.mailbox` 컬럼과 인덱스, 기동 시 자동). 새 설정 키·필수 환경변수는 없습니다.

## 보낸 메일

- 지금까지는 받은편지함(INBOX)만 가져왔고 메시지에 보낸 메일이라는 표시도 없었습니다. IMAP 어댑터에 폴더 목록·선택 함수가 있었지만 아무 곳에서도 호출하지 않았습니다.
- **IMAP 계정**은 받은편지함 다음에 같은 세션에서 서버의 보낸편지함을 가져옵니다. 서버가 RFC 6154 `\Sent` 속성을 알려 주면 그 폴더를, 아니면 `Sent`·`Sent Items`·`Sent Messages`·`Sent Mail`·`보낸편지함` 같은 흔한 이름을 찾습니다. 이름은 계층의 마지막 부분을 modified UTF-7에서 풀어 비교하므로 `INBOX.Sent`, `[Gmail]/Sent Mail`, `&vPSwuNO4ycDVaA-`(보낸편지함)도 찾습니다.
- IMAP 폴더는 UID 공간이 폴더마다 따로이고 UIDVALIDITY가 겹치는 서버도 있어, 보낸편지함 체크포인트는 `sent:` 접두사로 분리합니다. 접두사 없이 받은편지함과 UID가 겹친 보낸 메일은 "이미 받음"으로 건너뛰어진다는 것을 변이 테스트로 확인했습니다.
- 보낸편지함이 없거나, 목록을 못 받거나, 열 수 없어도 받은 메일 동기화는 성공합니다. 작업 통계에 `sent_seen`·`sent_new`·`sent_duplicate`·`sent_failed` 가 따로 남아 `new` 는 계속 받은 새 메일만 뜻합니다.
- **Postra에서 보낸 메일**은 SMTP 발송이 확인된 순간 보낸 메일로 기록합니다. POP3에는 보낸편지함이 없고 SMTP 제출을 보낸편지함에 저장하지 않는 서버도 많아서입니다. 결과가 불확실한 발송(`uncertain`)은 기록하지 않고, 기록은 요청이 끝나도 완료됩니다. 서버가 제출된 메일을 보낸편지함에 저장하면(헤더가 추가돼 바이트는 다름) 같은 Message-ID로 알아보고 두 번 저장하지 않습니다.
- 보낸 메일은 받은 메일 기능에 섞이지 않습니다. 받은편지함·중요·보관·스누즈와 검색의 기본 보기, 자동화 규칙, AI 분류, 임베딩(따라서 시맨틱·하이브리드 검색)은 받은 메일만 다룹니다. 답장은 원래 메일과 같은 스레드로 묶여 스레드 보기에 함께 나타납니다.
- **MCP `mail_sent_search`**: 필터 없이 부르면 보낸 메일 전체를 최신순으로 나열하고, 수신자·제목·키워드·기간·첨부 여부·계정으로 좁힙니다. 입력에 폴더 선택이 없어 받은 메일을 돌려줄 수 없고, `mail_search` 와 같은 `mail.search` 권한을 요구하며 같은 응답 스키마를 씁니다. 본문은 `mail_message_get` 으로 봅니다. 검색 API의 `folder=sent` 도 같은 보기입니다.

## 메일 동기화가 멈춘 채 돌아오지 않던 문제

IMAP IDLE 감시와 리더 선출에는 테스트가 없었고, 여러 결함이 겹쳐 있었습니다. IDLE 감시 재현 테스트 5건은 모두 이전 코드에서 실패합니다.

- **끝난 IDLE 감시가 "실행 중"으로 남았습니다.** 감시 루프는 패닉이나, IDLE 사이에 본 짧은 대기 전환에서 스스로 끝나는데, 감독자는 60초마다만 리더 여부를 보았습니다. 그보다 짧은 전환이면 항목이 남아 **그 계정을 프로세스 재시작 전까지 다시 감시하지 않았습니다.** 이제 각 감시가 종료를 알리고 감독자는 끝난 감시를 없는 것으로 봅니다. 재시작은 다음 점검에 해서, 연결 시 반복 패닉하는 계정이 폭주하지 않습니다.
- 감독자가 리더 전환마다 즉시 점검합니다. 대기로 내려가면 IDLE을 곧바로 끊고 리더가 되면 곧바로 다시 붙습니다.
- 계정 목록 조회가 한 번 실패하면 빈 목록으로 읽어 **모든 IDLE 연결을 끊었습니다.** 이제 실행 중인 감시를 유지합니다.
- 실행 중인 감시는 시작 때의 계정 설정을 써서, 호스트나 비밀번호를 고쳐도 재연결하지 않았습니다. 연결 설정이 바뀌면 재연결합니다(동기화 상태만 바뀐 경우는 제외).
- **리더 lease 갱신에 제한 시간이 없었습니다.** SQLite 저장소는 프로세스 전체가 연결 하나를 쓰므로, 긴 쓰기 뒤에 줄 선 갱신이 선출 루프를 무기한 멈췄습니다. 갱신은 5초로 제한합니다.
- 갱신이 실패해도 상태를 바꾸지 않아, lease가 만료된 뒤에도 리더를 자처했습니다(다중 노드에서 두 리더가 같은 계정을 동기화). 이제 마지막으로 쓴 lease가 유효한 동안만 리더를 유지하고, 만료되면 내려오며 장애 화면에 `leader-election` 경고를 남깁니다.
- 스스로 끝난 감시가 자기 컨텍스트를 해제하지 않아 재시작마다 워커 컨텍스트에 자식이 쌓이던 문제도 고쳤습니다(gosec G118).

## 로그인 화면과 silent SSO

- 로그인 화면이 내부 앱 스토어와 같은 구성이 됐습니다. SSO가 설정돼 있으면 **조직 계정으로 로그인**이 주 동작이고, 로컬 로그인은 접힌 토글 뒤에 있습니다. silent 시도가 거절된 경우(`sso=none`)는 이유를 안내합니다. SSO가 없으면 전처럼 로컬 폼이 바로 보입니다.
- **silent SSO에서 로그아웃이 유지되지 않았습니다.** 로그아웃은 Postra 세션만 끝내고 Keycloak 세션은 남기는데, `prompt=none` 을 막는 표시를 탭 단위(`sessionStorage`)로 저장했기 때문에, 새 탭이나 다시 연 탭에서 곧바로 재로그인됐습니다. 관리자 가이드의 "로그아웃한 뒤 다시 열어도 자동으로 로그인되지 않는다"와 어긋났던 동작입니다. 이제 브라우저 단위(`localStorage`)로 남기고 다음 로그인 때만 지웁니다. 로그인·초기 설정·오류 화면에서는 silent 시도를 하지 않습니다.
- 임베드된 `/app` 번들을 이 소스로 다시 빌드했습니다.

## MCP OAuth: 미연결 Keycloak 사용자 자동 연결

- 연결된 Postra 사용자가 없는 Keycloak identity는 웹 UI에 한 번 로그인할 때까지 거부됐습니다. 이제 첫 MCP 요청(또는 DCR 프록시의 토큰 교환)에서 **브라우저 첫 SSO 로그인과 같은 규칙**으로 연결합니다. 두 경로가 같은 함수를 쓰므로 MCP가 웹보다 느슨해질 수 없습니다.
- 본인 소유가 분명한 로컬 계정이 있으면 연결합니다. 다른 Keycloak subject에 연결된 계정은 이메일이 같아도 가져가지 않습니다. 없으면 `auth.oidc.auto_provision` 이 켜져 있을 때만 만들고, 꺼져 있으면 거부 사유가 그 설정을 가리킵니다. 동시에 들어온 첫 요청들은 계정 하나만 만듭니다.
- 관리자 역할은 access token의 `groups` 가 관리자 그룹을 담을 때만 부여합니다. groups mapper가 없는 access token이면 일반 사용자로 만들어집니다.
- 연결은 모든 토큰 검사를 통과한 뒤에만 일어나고, 이 경로는 웹 client secret을 풀지 않습니다.

## 업그레이드 및 호환성 주의사항

DB·SecretStore·ObjectStore·KEK를 백업하고 유지한 상태에서 실행 파일 또는 컨테이너 이미지를 교체한 뒤 재시작하세요.

- **DB 마이그레이션**: 기동 시 `messages.mailbox`(기본값 `inbox`)와 `(user_id, mailbox, date)` 인덱스를 추가합니다(SQLite·PostgreSQL). 기존 메일은 모두 받은 메일로 남습니다. 큰 메일함에서는 인덱스 생성에 시간이 걸릴 수 있습니다.
- **업그레이드 후 첫 동기화**가 IMAP 계정의 보낸편지함 전체를 가져옵니다. 동기화 1회 상한(`sync.max_per_sync`)이 보낸편지함에도 따로 적용되므로 큰 보낸편지함은 여러 번에 나눠 들어옵니다.
- **되돌리기 주의**: 보낸 메일이 저장된 뒤 v0.23.x 로 되돌리면, 이전 버전은 `mailbox` 를 모르므로 보낸 메일이 받은편지함·검색·AI 기능에 섞여 보입니다. 되돌려야 한다면 백업한 DB로 복원하세요.
- **MCP OAuth 정책 변경**: `auth.oidc.auto_provision` 이 켜져 있으면(기본값) Keycloak에 로그인한 사용자가 첫 MCP 요청에서 Postra 사용자로 만들어집니다. 원치 않으면 이 설정을 끄세요. 이 설정은 웹 SSO 최초 로그인에도 똑같이 적용됩니다.
- **로그인 화면**: SSO가 설정된 배포에서 로컬 로그인 폼은 "로컬 계정으로 로그인" 토글을 눌러야 보입니다. SSO가 없는 배포는 전과 같습니다.
- **silent SSO**: 로그아웃한 브라우저는 다음에 직접 로그인할 때까지 자동 로그인하지 않습니다.
