# Postra v0.23.3 — MCP 도구 오류의 스키마 위반 수정

OAuth 로 연결한 MCP 클라이언트가 실패한 호출마다 스키마 검증 오류를 보고하던 문제를 고친 패치 릴리즈입니다. 새 설정 키, DB 마이그레이션, 새 필수 환경변수는 없습니다.

## 오류 응답이 공표한 출력 스키마를 위반하던 문제

- 모든 도구는 성공 응답 Go 타입에서 추론한 출력 JSON Schema 를 공표하며, 이 스키마는 `additionalProperties` 를 닫고 성공 필드를 필수로 둡니다. 그런데 실패한 호출은 `{code, message, details, trace_id}` 오류 봉투를 `structuredContent` 에 실어 보냈습니다. 이 봉투는 어떤 도구의 성공 스키마도 만족할 수 없으므로, 응답을 검증하는 클라이언트(MCP TypeScript SDK 가 그렇게 합니다)는 거부된 호출마다 스키마 위반을 보고했습니다.

  ```text
  mail_account_get → unexpected additional properties ["code" "message" "trace_id"]
  mail_message_get → /properties/message: has type "string", want "object"
  ```

- **MCP 키에서는 거의 드러나지 않고 OAuth 에서만 드러났습니다.** 키는 넓은 scope 를 갖기 때문에 실패하는 호출이 드뭅니다. OAuth 토큰은 Keycloak 이 발급한 scope 만 가지므로 광고된 도구 92 개 중 대부분이 거부됩니다. 기본 `mail.read mail.search` 토큰으로 전체 도구를 훑으면 응답 65 건 중 **49 건이 스키마 검증에 실패**했고 그중 39 건이 `insufficient_scope` 였습니다.
- v0.23.2 이전에는 이 증상이 보이지 않았습니다. OAuth scope 거부가 HTTP 403 이어서 전송이 먼저 끊어졌고, 봉투가 결과로서 클라이언트에 도달하지 못했기 때문입니다. v0.23.2 에서 세션이 유지되도록 고치면서 원래 있던 이 결함이 OAuth 호출 대부분에 드러났습니다.
- 오류 결과는 이제 `structuredContent` 를 싣지 않습니다. MCP 계약상 structured content 는 공표한 출력 스키마를 따라야 하고, 오류 채널은 `isError` 와 content 의 상세입니다. 오류 봉투는 모델이 읽는 text content 로 그대로 전달되며, 스키마 검증 대상이 아닌 `_meta.postra_error` 에도 같은 객체를 실어 기계 판독용 사본을 유지합니다. `_meta.trace_id` 는 그대로입니다.
- `{code, message, details, trace_id}` 오류 계약과 도구 메타데이터의 `errorContract` 는 바뀌지 않았습니다.

## 검증

- 실제 SDK 클라이언트를 OAuth 세션으로 붙여 도구 전체를 호출하고, 구조화된 성공 응답은 클라이언트가 받은 스키마를 만족하는지, 거부 응답은 structured content 를 싣지 않는지 양쪽을 단언하는 회귀 테스트를 추가했습니다. 수정 전 49 건 실패, 수정 후 0 건입니다.
- 전체 Go 테스트, Go vet, `gofmt` 검사, `go mod tidy` 무변경
- CI 와 같은 플래그의 `gosec -severity medium -exclude-dir=scripts ./...`: exit 0 · Issues 0
- 프런트엔드 소스 변경이 없어 포함된 `/app` 번들은 v0.23.2 와 동일

테스트는 로컬 루프백 서버와 모의 Keycloak·메일·AI 서비스를 사용하며 운영 메일 서버나 운영 데이터에 접근하지 않습니다.

## 업그레이드 및 호환성 주의사항

DB 마이그레이션, 새 설정 키, 새 필수 환경변수는 없습니다. DB·SecretStore·ObjectStore·KEK를 백업하고 유지한 상태에서 실행 파일 또는 컨테이너 이미지를 교체한 뒤 재시작하세요.

- OAuth 로 MCP 를 사용 중이라면 v0.23.2 와 함께 교체하세요. v0.23.2 단독으로는 연결은 유지되지만 거부된 호출마다 클라이언트가 스키마 오류를 보고합니다.
- 도구 오류 결과에서 `structuredContent` 가 사라집니다. 이를 읽던 자체 클라이언트는 text content 의 JSON 또는 `_meta.postra_error` 를 보도록 바꾸세요. 두 곳 모두 같은 `{code, message, details, trace_id}` 객체입니다. 성공 응답의 `structuredContent` 는 그대로입니다.
- 토큰 수용 정책, 사전 등록 client 연결, API Key, REST OIDC Bearer 동작은 v0.23.2 와 같습니다. [Keycloak OAuth MCP 설정](https://github.com/hkjang/postra/blob/v0.23.3/docs/MCP_OAUTH.md)과 [v0.23.2 릴리즈 내용](v0.23.2.md)을 참고하세요.
