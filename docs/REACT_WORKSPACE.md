# React AI 업무 메일 워크스페이스

## 접속 및 전환

- 새 화면: `http://서버:8480/app/`
- 기존 화면: `http://서버:8480/ui/`
- REST API와 MCP 주소는 바뀌지 않습니다. 기존 사용자·메일 계정·SSO·데이터를 그대로 사용합니다.
- 관리자가 SSO 자동 로그인을 활성화한 경우 `/app/` 첫 진입에서도 기존 `prompt=none` 흐름을 사용합니다. 탭당 시도 제한, 자동 로그인 거절, 명시적 로그아웃 및 저장소 차단 시 반복 로그인 방지 규칙을 적용합니다.
- `/ui` 상단의 **새 워크스페이스**와 `/app` 왼쪽 아래 **기존 UI**로 양쪽 화면을 오갈 수 있습니다. 전환 검증이 끝나기 전에는 `/ui`를 제거하지 않습니다.

## 화면과 작업 흐름

| 화면 | 제공하는 기능 |
| --- | --- |
| 받은메일 | 가상 스크롤·추가 페이지 조회, 중요·첨부·오늘·보관함 필터, 키워드·의미·통합 검색 |
| 메일 상세 | 본문과 AI Insight 동시 보기, 중요 표시·보관, 답장·전체 답장·전달, 안전한 첨부 다운로드 |

| 작성 | TipTap 서식·표·링크·글꼴·색상, 공지/업무 공유 헤더, HTML 직접 입력, 일반 텍스트, AI 다듬기 |
| 발송 | 미리보기 → 내용 확인·승인 → 승인한 메일 발송, DLP·외부 수신자 경고, 결과·재시도·불확실 상태 확인 |
| 내 업무 | 최근 메일의 중요·다시 확인·첨부 확인·참고 신호 분류 |

상단 검색은 `Ctrl+K` 또는 `⌘K`, 입력 중이 아닐 때 `/`로 열 수 있습니다. `C`는 새 메일, 메일 목록에서 `J/K`는 이전/다음 선택입니다. 상단에서 밝은/어두운 테마와 목록 밀도를 바꿀 수 있습니다. 좁은 화면에서는 메일 목록과 본문이 한 화면씩 전환되며 메뉴 버튼으로 사이드바를 엽니다.

## 작성·승인과 저장

작성 내용은 **초안 저장**으로 서버에 저장합니다. 미리보기를 열 때도 현재 내용을 먼저 저장합니다. 저장하지 않은 상태로 다른 화면으로 이동하거나 로그아웃하면 확인하며, 저장·발송 처리 중에는 이동을 막습니다.

서식 메일은 안전하게 정리된 HTML과 일치하는 일반 텍스트를 함께 전송합니다. 미리보기 이후 본문이나 수신자가 바뀌면 다시 승인해야 합니다. 발송 요청 결과가 불확실하면 재전송하지 않고 **발송 기록**을 확인하도록 안내합니다. AI는 사용자의 요청으로 분석하거나 초안을 만들 뿐, 자동으로 발송하지 않습니다.

## 현재 백엔드 기능에 따른 경계

- 기존 API에는 서버 전체 초안 목록이 없습니다. 현재 초안 화면은 **현재 브라우저 세션에서 작업한 초안**과 **ID로 기존 초안 열기**를 제공합니다. 서버에 저장된 초안은 사라지지 않지만 최근 목록은 새로고침 시 초기화됩니다. 전체 초안함은 읽기 전용 목록 API 추가가 필요한 별도 단계입니다.
- 기존 메시지 모델에 읽음/안읽음 상태가 없어 미확인 상태를 임의로 표시하지 않습니다.
- 기존 발송 API에는 첨부파일 업로드가 없어 작성 화면에 미지원 안내를 표시합니다. 수신 첨부의 보안 검사·다운로드는 유지합니다.
- 업무 상태는 서버의 `open`, `pending`, `resolved` 세 가지를 사용합니다. 5단계 상태나 외부 서비스 자동 등록을 화면에서 임의로 만들지 않습니다.
- 고급 방문 추적/CSP 출처 관리 등 아직 별도 전환하지 않은 운영 기능은 `/ui/admin/settings`에서 계속 사용할 수 있습니다.

## 인증·개인정보

기존 로컬 로그인과 Keycloak OIDC를 사용합니다. 브라우저에는 HttpOnly 세션 쿠키만 사용하고 API 토큰을 localStorage에 넣지 않습니다. 쿠키 인증으로 API를 변경할 때는 서버 세션에 연결된 CSRF 토큰과 동일 출처 검사를 모두 적용합니다. 프록시는 공개 Host를 보존하거나 `X-Forwarded-Host`·`X-Forwarded-Proto`를 신뢰 가능한 값으로 덮어써야 합니다.

관리자도 자신의 메일 계정과 본문만 볼 수 있습니다. 사용자별 브라우저 캐시를 분리하고, 세션 변경·다른 탭 로그인·로그아웃 시 이전 사용자의 데이터가 재사용되지 않게 합니다. 메일 HTML은 격리된 iframe과 별도 CSP로 표시합니다. AI·메일 비밀번호는 쓰기 전용이며 비워 두면 기존 값을 유지하는 설정에는 가짜 마스킹 값을 전송하지 않습니다.

## 빌드·오프라인 운영

React 19·TypeScript·Vite, Radix 기반 UI, Tailwind, React Router, TanStack Query, Zustand, TipTap과 가상 목록을 사용합니다. Vite의 결과를 `internal/transport/spa/assets`에 만들고 Go `embed`로 단일 실행 파일에 포함합니다. 글꼴·아이콘·코드 모두 로컬 번들이며 운영에는 Node 프로세스나 인터넷 연결이 필요 없습니다.

프런트엔드 변경 시 `make frontend`, 전체 빌드는 `make build`를 실행하고 생성된 자산도 커밋합니다. CI는 잠금 파일로 다시 빌드하여 자산 최신성을 검사합니다. 필요한 Go 모듈을 미리 준비한 환경에서는 커밋된 자산으로 `make build-offline`을 사용할 수 있습니다. 자세한 내용과 브라우저 테스트 방법은 [web/README.md](../web/README.md)를 참고하세요.
