# React AI 업무 메일 워크스페이스

## 접속과 기존 설치 이전

공식 화면은 `http://서버:8480/app/` 입니다. 로그인·최초 설정은 `/app/login`, `/app/setup`이며 인증 API는 `/auth/*` 입니다. 기존 사용자·메일·초안·SSO·암호화 데이터를 그대로 사용하며 재설치하거나 데이터를 삭제할 필요가 없습니다.

v0.20에서 이전 Go 템플릿 UI를 제거했습니다. 임시 이전용 URL은 다음 세 종류뿐이며 v1에서 제거할 예정입니다.

| 기존 URL | 동작 |
| --- | --- |
| `/ui`, `/ui/` | 301 → `/app/` |
| `/ui/messages/{id}` | 301 → `/app/messages/{id}` |
| `/ui/auth/oidc/callback` | 307 → `/auth/oidc/callback`, 기존 쿼리 보존 |

다른 `/ui/*` URL은 404입니다. 예전 로그인·관리·정적 파일은 제공하지 않으며, 프록시가 `/app/`, `/auth/`, `/api/`를 모두 전달하도록 수정하세요. REST `/api/*`는 유지하며 `/api/v1/*` 별칭도 제공합니다.

### Keycloak callback 이전

1. Keycloak의 Valid Redirect URIs에 `https://<postra-host>/auth/oidc/callback`을 추가합니다.
2. `/app/admin?category=auth`에서 Postra의 Redirect URL을 동일한 값으로 저장합니다.
3. 대화형 로그인, 이미 로그인한 사용자의 자동 로그인, 새 탭·명시적 로그아웃·깊은 링크를 확인합니다.
4. 검증 후 IdP의 예전 callback 등록값을 제거합니다. v1 전에 모든 설치에서 이전을 완료하세요.

기존 저장값을 자동으로 바꾸지 않습니다. 기존 callback URI를 사용 중이면 307 shim으로 새 인증 handler에 도착하지만, 토큰 교환의 `redirect_uri`는 기존 저장값과 정확히 동일하게 유지합니다. OIDC Client Secret은 관리자 저장값이 초기 환경변수보다 우선하며, 명시적으로 해제한 값을 오래된 환경변수에서 되살리지 않습니다.

자동 로그인은 관리자 설정이 켜진 경우에만 `prompt=none` 최상위 이동으로 시도합니다. 탭당 시도 제한, 자동 로그인 거절, 로그아웃 및 브라우저 저장소 차단 시 반복 방지 규칙을 유지합니다. 로그인 실패 사유는 60초 서명된 일회용 HttpOnly 쿠키를 통해 표시하며 code/state는 화면 URL에 남기지 않습니다.

## 화면과 작업 흐름

| 화면 | 제공 기능 |
| --- | --- |
| 받은메일 | 읽음/안읽음, 중요·첨부·오늘·보관·다시 확인, 계정/주소/제목/라벨/기간 상세 필터, 키워드·의미·통합 검색, 일괄 작업 |
| 메일·대화 | 전체 스레드, 텍스트/격리 HTML, 첨부 검사와 다운로드, 답장·전달, AI Insight, 날짜 지정 다시 보기, 원본 연결 액션 만들기 |
| 작성·초안 | 서버 영구 초안함, Text/Markdown/HTML/자동 서식, 안전한 인라인 템플릿, TipTap, 복수 서명, 파일·본문 이미지, AI 선택 영역 제안, 답장·전달 원문 확인 |
| 발송 | 미리보기 → 내용 확인·승인 → 명시적 발송, DLP/수신자/첨부 경고, 불확실 결과와 재시도 상태 |
| 업무·액션 | 5단계 업무, 담당/SLA/메모, 기한별 건수·필터·기한순 정렬, 메일 선택 액션 생성, 제목·담당자 검색, 검토·승인·완료·참조 JSON |
| Ask·브리핑 | 내 메일·업무·액션 근거 및 검색 조건, 한정된 근거 표시, 기간별 요청·기한·소식 |
| 설정 | 서버에 저장된 개인·계정 설정, 출처/관리자 잠금 표시, 테마·밀도·글자 크기·읽기 패널·미리보기·AI·검색·작성 기본값 |
| 운영 콘솔 | `/app/admin` 카테고리별 시스템 설정·SSO 프로비저닝·사용자·장애·감사·MCP·이전 메일 정리 |
| 방문 추적 | `/app/admin/tracking`, 기본 꺼짐, 독립 iframe/CSP와 허용 출처·위반 관리 |

`Ctrl/⌘+K` 또는 입력 중이 아닐 때 `/`로 명령창을 엽니다. 메일 목록에서 `J/K`, `R/A/F/E`, `G I`·`G W`를 지원하며 입력·IME·모달에서는 충돌을 막습니다. 화면의 단축키 도움말을 확인하세요. 좁은 화면에서는 메뉴 버튼과 한 화면씩 전환되는 목록/본문을 사용합니다.

## 글자 크기와 읽기 환경

업무 화면의 글자 크기는 공통 기준을 사용합니다. 기본 크기는 본문·입력·버튼 15px, 보조 설명 13px, 배지 12px, 카드 제목 16px, 섹션 제목 18px, 페이지 제목 24px입니다(브라우저 기본 글꼴 16px 기준). `/app/settings`의 **화면 글자 크기**에서 크게를 저장하면 약 12.5% 확대되며 재접속에도 유지됩니다. 화면 밀도는 여백만 변경합니다. 받은 HTML 메일과 작성한 메일 본문의 서식은 별도로 보존합니다.

## 개인정보와 저장

관리자도 자신의 메일 계정과 본문만 볼 수 있습니다. 사용자 전환 시 이전 사용자의 브라우저 캐시를 폐기하며 API와 저장소도 소유권을 확인합니다. 쿠키는 HttpOnly이고 API 토큰을 localStorage에 저장하지 않습니다. 변경 요청에는 동일 출처와 CSRF 검증을 적용합니다.

수신 HTML은 발송 HTML과 별도 정책으로 처리합니다. 외부 이미지는 기본 차단하고 관리자 정책 범위에서만 이번 한 번·발신자·도메인 허용/취소를 제공합니다. 이미지 요청은 IP와 읽음 여부를 전달할 수 있으므로 신뢰할 수 있는 발신자에만 허용하세요. data/SVG와 식별 가능한 추적 픽셀을 제거하지만 위장된 추적 URL을 모두 탐지할 수는 없습니다.

수신 본문의 `http`, `https`, `mailto` 링크는 클릭할 때 새 탭(메일 주소는 시스템 메일 처리기)으로 엽니다. 원래 메일 화면은 유지하고 새 창에 opener와 referrer를 전달하지 않습니다. 본문 프레임의 스크립트·폼·부모 화면 이동 차단과 외부 이미지 정책은 그대로 유지합니다. 위험한 스킴, 인증정보가 포함된 URL, Postra 내부 경로로 오인될 수 있는 상대 링크는 활성화하지 않습니다. 기존에 저장된 HTML도 열 때 다시 정제하므로 메일 재수집은 필요하지 않습니다.

액션·초안·작업 등의 빈 목록은 빈 상태로 표시합니다. 예상과 다른 서버 응답은 빈 목록으로 숨기지 않고 재시도 오류로 표시하며, 한 페이지의 렌더링 오류가 전체 메뉴를 사라지게 하지 않습니다. 정기 세션 확인 중 네트워크 오류·5xx·잘못된 응답은 미저장 편집을 유지하지만, 명시적 인증 만료나 다른 탭의 로그아웃은 개인 화면을 즉시 닫습니다. 서버가 `authenticated:false`를 반환하면 사유에 관계없이 로그아웃으로 처리합니다. 인증 저장소 장애와 실제 세션 만료를 백엔드에서 구분하는 개선은 별도 후속 점검 대상입니다.

읽음 상태는 본인 메일의 Postra 로컬 상태이며 IMAP 서버 플래그를 바꾸지 않습니다. 이전 버전에는 읽음 이력이 없어 마이그레이션된 메일은 처음에 안읽음으로 표시됩니다. 메일 삭제는 IMAP 원본을 지우지 않으며, 법적 보존 정책은 계속 적용합니다.

초안은 서버에 저장하므로 브라우저 캐시를 비워도 목록이 유지됩니다. 저장하지 않은 편집으로 이동·로그아웃하면 확인하고 저장·발송 처리 중에는 이동을 막습니다. 승인에는 본문/서식/수신자/첨부의 정확한 버전과 해시가 묶입니다. AI는 분석·초안만 만들며 자동 발송하지 않습니다.

답장·전체 답장·전달 초안에서는 원문 패널을 펼쳐 발신자·수신자·날짜·내용을 확인할 수 있습니다. 펼칠 때 본인에게 조회 권한이 있는 원문만 가져오며 읽음 상태나 초안 본문·승인을 변경하지 않습니다. 원문이 삭제되었거나 조회에 실패해도 작성 내용은 유지됩니다. HTML 전용 원문은 외부 이미지가 차단된 격리 프레임에서 표시합니다.

## 빌드·검증·폐쇄망 운영

React·TypeScript·Vite·TipTap과 글꼴/아이콘은 `internal/transport/spa/assets`로 빌드해 Go 실행 파일에 포함합니다. 운영에는 Node 프로세스나 외부 CDN/인터넷이 필요 없습니다. 개발용 Vite는 `/auth`와 `/api`를 Go 서버로 프록시하며 쿠키/Origin 보안을 끄지 않습니다.

`make frontend`, `make build`와 `npm run test:e2e`로 빌드·실제 브라우저 검증을 실행합니다. 사전 준비한 Go 도구/모듈과 커밋된 자산으로는 `make build-offline`을 사용할 수 있습니다. [개발 안내](../web/README.md), [이전 기능/보안 검증 기록](LEGACY_PARITY.md), [설정 안내](SETTINGS.md)를 참고하세요.
