# Generated canonical core API contracts

The checked-in contract is intentionally **partial**, not a specification of every Postra REST endpoint or MCP tool. Its current scope is settings catalogs/preferences, Ask input/evidence response, deterministic mail rendering/templates, draft create/read/update, send preview, attachment mutation metadata, and personal signatures.

The Go DTOs remain authoritative. `internal/transport/httpapi/contracts.Registry` explicitly selects DTOs from `internal/application`, `internal/domain`, and `internal/mailrender`; the cached `github.com/google/jsonschema-go` dependency infers their fields. The generator adds only known transport defaults and JSON encoding corrections. It writes:

- `api/contracts.schema.json`: JSON Schema 2020-12 `$defs` for the selected DTOs.
- `api/openapi.json`: OpenAPI 3.1.0 with canonical `/api/v1` server paths and the covered operations.
- `web/src/api/contracts.generated.ts`: TypeScript wire types derived from those same generated schemas. Settings, Ask and compose rendering consumers import these types instead of maintaining duplicate field definitions.

Generate from the repository root:

```sh
go run ./cmd/postra-contracts
go run ./cmd/postra-contracts -check
go test ./internal/transport/httpapi/contracts
go test ./internal/transport/httpapi -run TestCanonicalCoreContractResponses
```

`-check` never writes: it compares all generated bytes with checked-in goldens and fails with the stale paths and regeneration instructions. The contracts CI workflow performs this check and tests actual HTTP response JSON against the schemas. The ordinary Go test suite also detects drift, while the frontend typecheck catches affected TypeScript consumers. Review and commit the generated diff alongside any DTO change; do not edit generated files by hand. Generation needs no running server, database, LLM, registry download beyond the existing module cache, or Node server.

## Exactness and limits

The generated fields preserve `omitempty`, nullable pointers/slices/maps, promoted embedded fields, and Go JSON names. A nil embedded `*Analysis` omits its promoted fields; nil lists can be `null`, so the updated UI handles them without crashing. The generator explicitly documents the small request differences from marshal tags: an omitted draft kind means `new`, the URL supplies a draft ID, and a reset-only settings PATCH can omit `values`. Settings `secrets` is write-only. No environment values, real secrets, account content, or live configuration is loaded into contract artifacts.

Schemas describe wire shape and selected defaults, not every runtime restriction. Application ownership, administrator locks, per-key MCP scopes, enabled capabilities, scanner/size limits, semantic validation, revision conflict checks, and the explicit preview→approval→send flow remain authoritative. Schema validation in these tests does not add a new production validation layer.

`/api/v1` is canonical and `/api` is a compatibility alias to the same handlers. The OpenAPI snapshot documents cookie/bearer authentication and cookie-mutation CSRF requirements but does not contain usable credentials. The separate MCP gateway catalog remains the source for MCP tool permissions and full tool discovery. Auth/setup, settings probes, other admin operations, binary downloads, SSE, approval issuance, and send endpoints are outside this bounded OpenAPI snapshot; their existing integration tests continue separately. Do not interpret omission as removal or permission to call an operation without its normal guards.
