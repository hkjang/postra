# Ask Postra

`/app/ask`, `POST /api/v1/qa`, MCP `mail_question_answer`와 `mail_ask`는 같은 `App.Ask` 서비스를 사용한다. 기존 `question`/`account_id` 호출과 `Analysis` 응답 필드는 유지하며 `retrieval` 근거 메타데이터를 추가한다.

입력은 질문, 소유 계정, `mode`(auto/keyword/semantic/hybrid/work/actions), 명시적 `search_text`, 발신자, `since`/`until` Unix 초, IANA `time_zone`, `incomplete_only`다. 시작은 포함, 종료는 미포함이다. UI의 종료일은 해당 날짜의 다음 날 자정으로 변환한다. 기준 시각은 발신 메일의 Date이며 수신·수집 시각을 뜻하지 않는다.

auto는 업무·Action 단어를 작은 결정적 규칙으로 구분하고 나머지는 개인 검색 기본값을 사용한다. 오늘·어제·지난주·이번 달·최근 7일 및 일부 영어 표현의 날짜 범위를 인식한다. 명시적 기간이 항상 우선한다. 모든 자연어 조건을 정확히 해석하는 범용 계획 Agent는 아니다. 정확한 업무 범위는 UI의 검색 조건을 지정한다.

IANA 시간대 데이터는 Go 실행 파일에 포함한다. 폐쇄망 scratch 이미지에서도 별도 OS tzdata 설치 없이 브라우저가 전달한 `Asia/Seoul` 등의 날짜 범위를 해석할 수 있다.

의미/통합 검색이 불가능하면 키워드 검색으로 전환한다. 자연어 질문 검색 결과가 없으면 선택 기간의 최근 메일을 참고할 수 있지만 이 사실을 응답과 모델 지시문에 명시한다. 명시적 검색어·기간·계정·발신자 조건은 대체 검색에서도 제거하지 않는다. 업무 검색어는 제목·담당자, Action 검색어는 제목·설명을 검사한다.

업무/Action 조회는 최근 최대 200건, AI 근거는 최대 6개 메일, 전체 AI 본문 입력은 문자 예산으로 제한한다. 각 메일의 본문 일부, 업무 상태·SLA·최근 메모, 연결된 Action 최대 2개, 가능한 첨부 추출 일부를 비신뢰 데이터로 전달한다. 전체 메일함을 빠짐없이 조사했다는 의미가 아니다. 원문 소유권은 관리자에게도 동일하게 적용한다.

응답의 `retrieval`은 실제 제공한 message ID·제목·발신자·날짜·업무 상태·Action ID와 검색 방식·기간·경고를 포함한다. 모델이 만들어낸 인용 ID는 제공한 근거 집합과 대조해 제거한다. UI는 실제 근거 제목과 모델의 인용 여부를 구분해 표시한다. confidence는 모델 자체 평가이지 정확도 보증이 아니다.

업무가 미완료라는 사실은 실제로 회신하지 않았다는 증거가 아니다. 보내기·수신 스레드 전부를 대조하지 않았으므로 미회신을 단정하지 않도록 지시하고 화면에서도 이 한계를 알린다. 이 기능은 조회/분석만 수행하고 업무 변경, 메일 발송, 외부 Task 생성을 실행하지 않는다.
