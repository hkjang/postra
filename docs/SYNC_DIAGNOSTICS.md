# 메일 동기화 실패 진단

메일 동기화 실패는 이 서비스에서 가장 심각한 오류다. 새 메일이 들어오지 않는데도 화면에는 한 줄만 남으면 운영자가 확인할 수 있는 것이 없다. Postra는 실패한 동기화마다 **어느 단계에서, 어떤 유형으로, 얼마나 걸려서** 멈췄는지를 기록하고, 작업 화면과 장애 화면에 함께 보여 준다.

기록되는 모든 값은 Postra 자신의 어휘 아니면 숫자다. 메일 서버가 보낸 문장은 비밀번호나 메일 내용을 되돌려 줄 수 있고 진단은 저장·표시되므로, **서버 응답 문장은 어디에도 남기지 않는다.** RFC로 정해진 응답 코드(IMAP RFC 5530, POP3 RFC 2449/3206)만 예외로 남는다.

## 어디서 보는가

| 위치 | 내용 |
| --- | --- |
| `/app/jobs`, `/app/jobs/<작업 ID>` | 작업별 "멈춘 지점": 요약 문장과 서버·명령·응답 코드·소요 시간·제한 시간·연결 시도·유지 중인 연결·시작 전 대기 |
| `/app/admin?category=system` | 실패·부분 성공 동기화의 장애 행. detail 에 같은 요약이 들어간다 |
| `GET /api/jobs`, `GET /api/jobs/{id}` | `diagnostic` 객체(아래 필드) |
| MCP `job_status` | 같은 `diagnostic` 객체 |

## 단계(stage)

단계는 세션이 지나가는 순서대로 기록된다. **앞의 세 단계는 서버에 패킷을 보내기 전**이므로, 여기서 멈춘 동기화는 서버 장애가 아니라 설정 문제다.

| stage | 화면 표기 | 의미·먼저 볼 것 |
| --- | --- | --- |
| `policy` | 관리자 정책 확인 | `mail.pop3_enabled`/`mail.imap_enabled`, `mail.tls_required`, 평문 허용 여부 |
| `secret` | 메일 비밀값 사용 | SecretStore·KEK 상태, 비밀값 재등록 필요 여부 |
| `host_check` | 서버 주소 확인 | 호스트 이름, 내부 DNS, 사설 IP 허용 정책 |
| `tcp_connect` | 서버 연결(TCP) | 포트, 방화벽, 서버 기동 여부 |
| `tls_handshake` | TLS 핸드셰이크 | 인증서 체인·신뢰 저장소, 보안 모드와 포트 조합 |
| `greeting` | 서버 환영 메시지 수신 | **동시 접속 수 제한**, 접속 빈도 제한, 차단 목록, 프록시. 그리고 **993/995 포트를 TLS 아닌 보안 모드로 접속한 경우** — 서버는 TLS 핸드셰이크를, Postra 는 환영 메시지를 서로 기다린다. TCP 는 붙었는데 서버가 세션을 시작하지 않은 상태다 |
| `starttls` | STARTTLS 전환 | 서버의 STARTTLS 지원, 핸드셰이크 전 평문 데이터 |
| `login` | 로그인 | 계정·비밀번호, 서버의 일시 거부 코드 |
| `select` | 메일함 선택 | 메일함 이름·권한(보낸 메일함 포함) |
| `enumerate` | 메일 목록 조회 | UIDL/FETCH 응답, 메일함 크기, 명령 제한 시간 |
| `fetch` | 메일 본문 수신 | 큰 첨부, 메일 최대 크기, 명령 제한 시간 |
| `list` | 메일함 목록 조회 | LIST 권한·응답 |
| `idle` | 실시간 대기(IDLE) | 유휴 연결 종료 정책, 프록시 타임아웃 |
| `logout` | 세션 종료 | (동기화 결과에는 영향 없음) |

## 실패 유형(class)

| class | 화면 표기 | 뜻 |
| --- | --- | --- |
| `timeout` | 제한 시간 안에 응답이 없었습니다 | 서버가 응답하지 않음 |
| `refused` | 서버가 연결을 거부했습니다 | 포트가 닫혀 있거나 방화벽이 차단 |
| `reset` | 서버가 연결을 끊었습니다 | RST/EPIPE — 동시 접속 제한에서 흔하다 |
| `closed` | 응답이 끝나기 전에 연결이 닫혔습니다 | EOF |
| `unreachable` | 서버까지 네트워크 경로가 없었습니다 | 라우팅·방화벽 |
| `dns_not_found` | 호스트 이름을 찾지 못했습니다 | 오타 또는 내부 DNS 미등록 |
| `dns_failed` | 이름 조회에 실패했습니다 | DNS 서버 장애·시간 초과 |
| `tls_certificate` | 서버 인증서를 신뢰할 수 없었습니다 | 내부 CA 미설치, SAN 불일치, 만료 |
| `tls_handshake` | TLS 핸드셰이크가 실패했습니다 | 프로토콜·암호 모음 불일치, 평문 포트에 TLS |
| `rejected` | 서버가 명령을 거부했습니다 | 응답 코드가 함께 기록된다 |
| `cancelled` | 작업이 취소되었습니다 | 사용자 취소, 종료, 리더 교체 |
| `config` | 서버에 연결하기 전에 중단되었습니다 | `policy`/`secret`/`host_check` 단계 |
| `other` | 알 수 없는 오류로 중단되었습니다 | 위에 해당하지 않음 |

## 시간 읽기 — "정말 시간 초과인가"

진단은 **그 단계의 소요 시간과 그 단계에 적용된 제한 시간**을 함께 남긴다.

- `제한 60.0초 중 60.0초 경과`: 그 단계가 자기 제한 시간을 다 썼다. 서버가 실제로 응답하지 않은 것이다.
- `제한 60.0초 중 0.9초에 중단(이 단계의 제한 시간에는 이르지 않았습니다)`: 제한 시간은 남아 있었는데 중단됐다. 시간 예산이 **다른 곳**에서 왔다는 뜻이다 — 연결 제한 시간(`sync.connect_timeout_sec`), 작업 취소, 프록시의 유휴 종료 등을 본다. 이 경우 "응답 시간 초과"만 보고 서버 성능을 조사하면 헛수고가 된다.

제한 시간 설정은 `sync.connect_timeout_sec`(기본 15초)와 `sync.command_timeout_sec`(기본 60초)다. **환영 메시지 읽기에는 연결 제한 시간(15초)을 적용한다** — 서버의 첫 응답은 즉시 오는 것이 정상이므로, 침묵하는 서버를 1분이 아니라 몇 초 만에 판정하고 동시 실행 슬롯을 돌려준다.

## 계정당 연결 하나

서버는 연결 수를 센다. 계정당 1~2개만 허용하고 그 이상은 **TCP 연결만 받아 놓고 환영 메시지를 보내지 않는 서버**가 많다. 그래서 Postra 는 한 계정에 인바운드 연결을 하나만 유지한다.

- IMAP 실시간 수신(IDLE) 감시는 새 메일 알림을 받으면 **자기 연결을 닫고** 동기화에 넘긴 뒤, 그 동기화가 끝나면 다시 연결한다. 감시와 동기화가 같은 계정에서 동시에 접속하지 않는다.
- 연결을 넘긴 사이에 도착한 메일은 재연결 때 메일함 개수가 늘어난 것으로 확인해 한 번 더 동기화한다. 늘지 않았으면 다시 동기화하지 않는다.
- 주기적·수동 동기화는 감시와 겹칠 수 있다. 계정당 **1개만** 허용하는 서버라면 관리자 설정의 **IMAP 실시간 수신(IDLE) 사용**(`mail.idle_enabled`)을 끄고 주기적 동기화만 사용한다. 끄면 수신이 자동 동기화 주기만큼 늦어진다.

## 연결 시도와 유지 중인 연결

- **연결 시도 N회**: 동기화는 일시적인 연결 실패(시간 초과, 거부, 끊김, 서버의 일시 거부 코드)를 다시 시도한다. 보통 최대 3회(2초·5초 간격)이고, **연결 수 제한처럼 보이는 실패**(환영 메시지·로그인 단계의 무응답/끊김, 서버의 일시 거부 코드)는 **2회까지만, 10초 뒤에** 시도한다 — 한도에 걸린 서버를 빠르게 재시도하는 것은 원인을 키우는 일이다. 비밀번호 거부, 인증서 불신, 호스트 없음, 정책 차단은 다시 시도하지 않는다 — 같은 결과가 반복될 뿐이다.
- `연결 시도 2회(이전 시도: 서버가 연결을 끊었습니다 — 재연결 후 진행)`: 결과는 성공이지만 서버가 첫 연결을 끊었다. 완전히 실패하기 전에 보이는 신호다.
- **이 서버에 유지 중인 연결 N개(이 계정 M개)**: 그 순간 이 노드가 열어 둔 인바운드 연결 수다. 계정 값이 2 이상이면 주기적 동기화가 실시간 감시와 겹친 순간이므로, **서버의 계정별 동시 접속 허용 수**를 확인한다(Dovecot `mail_max_userip_connections`, 상용 메일의 IMAP 동시 접속 제한 등). 호스트 값은 같은 서버를 쓰는 다른 계정까지 합한 수다.
- **시작 전 대기**: 동시 실행 제한(`sync.max_concurrent_syncs`)에서 순서를 기다린 시간. 이 값이 크면 계정 수에 비해 동시 실행 한도가 낮다.

## 보낸 메일함 패스

보낸 메일함 확인은 **받은 메일 동기화를 실패시키지 않는다.** 결과만 따로 기록된다.

| sent | 뜻 |
| --- | --- |
| `synced` | 보낸 메일함도 확인했다 |
| `throttled` | 실시간(IDLE) 동기화라 생략했다. IDLE 은 받은 메일만 알려 주므로 보낸 메일함은 10분에 한 번, 그리고 주기적·수동 동기화에서 확인한다 |
| `none` | 서버에 보낸 메일함이 없다(POP3 계정 포함) |
| `failed` | 확인에 실패했다. 실패한 단계·유형이 `sent_stage`/`sent_class` 에 함께 남는다 |

## 작업 상태가 말하는 것

- `failed`: 세션을 열지 못했거나, 목록을 얻지 못했거나, **가져오려 한 메일을 전부 가져오지 못했다.** 마지막 경우는 예전에는 "성공"으로 보였고, 이것이 새 메일이 없는 이유를 감췄다.
- `partially_succeeded`(일부 완료): 일부는 저장했고 일부는 실패했다. 장애 화면에는 경고로 기록된다.
- `succeeded`: 실패한 메일이 없다. 재시도가 있었거나 보낸 메일함 결과가 있으면 진단이 함께 남는다.

## 자주 보는 조합

| 진단 | 먼저 확인할 것 |
| --- | --- |
| `greeting` + `timeout`/`closed`, 포트 993/995 인데 보안 모드가 TLS 가 아님 | 계정의 보안 모드를 TLS 로. 서버는 첫 바이트부터 TLS 를 기다린다 |
| `greeting` + `timeout`/`reset`, 계정 연결 2개 이상 | 계정별 동시 접속 허용 수. 필요하면 `mail.idle_enabled` 를 끈다 |
| `login` + `rejected [AUTHENTICATIONFAILED]` | 비밀번호·계정. 이때만 계정이 `credential_error` 로 바뀐다 |
| `login` + `rejected [IN-USE]`/`[LOGIN-DELAY]`/`[LIMIT]` | 서버 부하·잠금. 비밀번호 문제가 아니며 계정 상태는 유지되고 재시도한다 |
| `tcp_connect` + `refused` | 포트, 보안 모드(암묵적 TLS 993/995 vs STARTTLS 143/110), 방화벽 |
| `tls_handshake` + `tls_certificate` | 컨테이너·노드의 내부 CA 설치와 인증서 SAN |
| `fetch` + `timeout`, 그 단계 제한 시간 소진 | 큰 첨부. `sync.max_message_bytes`, `sync.command_timeout_sec` |
| `enumerate` + `timeout` | 메일함이 매우 큼. 첫 동기화는 `max_messages` 로 나눠 받는다 |
| `config` 유형 | 서버 문제가 아니다. 위 `policy`/`secret`/`host_check` 항목 |

`sync.max_message_bytes` 를 0 이하로 두면 메일 한 건의 크기 제한이 **없어진다**(크기 때문에 건너뛰는 `oversize` 집계도 일어나지 않는다). 기본값은 50 MiB 다.

## 문의에 담을 것

작업 ID, 계정 ID, 화면의 요약 문장과 숫자(단계·유형·소요/제한 시간·연결 시도·유지 중인 연결)면 충분하다. **메일 서버 로그 원문, 비밀번호, 토큰, 메일 본문은 붙여 넣지 않는다.** Postra 가 남긴 값에는 이미 서버 문장이 포함되지 않는다.
